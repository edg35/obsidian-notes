# Securing and Governing Microsoft Copilot Cowork: An MSP Reference for a Regulated (Banking) Client

*Prepared for an MSP security engineer building an internal working reference and a client-facing policy document for a 5-person bank marketing department. Research current as of July 22, 2026. Copilot Cowork reached GA on June 16, 2026; this is a fast-moving product and several controls remain provisional or in preview — these are flagged inline.*

## TL;DR
- **Copilot Cowork is a cloud-hosted agentic system running under each user's delegated Microsoft Graph identity, primarily powered by Anthropic's Claude models (Anthropic acts as a Microsoft subprocessor). Its dominant risk is indirect prompt injection combined with Microsoft Graph oversharing — both already demonstrated in real attacks (PromptArmor, May 2026).**
- **The single most important fact for a bank: native Microsoft Purview DLP support for Cowork has NOT shipped as of research date — Microsoft's own Cowork/Purview matrix marks DLP with an "✕". Deploy compensating controls (Exchange transport-layer DLP, RAC/RCD, sensitivity labels, IRM + Adaptive Protection) and treat Cowork as pilot-only for this team until DLP ships.**
- **For a 5-user marketing team at a bank, the recommended posture is "security-oriented / balanced": scope Cowork to a named security group, harden identity with phishing-resistant MFA and risk-based Conditional Access, lock down SharePoint with RAC/RCD, require admin review of custom skills, block write-capable external plugins, and wire Cowork audit activity into Sentinel.**

## Key Findings
1. Cowork is GA worldwide since June 16, 2026, off by default, and gated behind usage-based billing (Copilot Credits, $0.01/credit PAYG). It requires a Microsoft 365 Copilot license plus an Exchange Online mailbox. It is now managed as an "agentic system" under **Agents > All Agents** in the M365 admin center — the old Frontier-preview agent toggle no longer governs access.
2. The core risk model is (a) indirect prompt injection via any untrusted content Cowork reads (email, Teams, calendar, SharePoint/OneDrive files, plugin responses, web content, custom skills), and (b) Graph permission inheritance/oversharing. PromptArmor demonstrated a working file-exfiltration attack against Cowork via a poisoned SKILL.md.
3. SharePoint governance (RAC, RCD, Block Download, Site Access Reviews) is the primary input-side control and is available at no extra cost to Copilot-licensed tenants via SharePoint Advanced Management.
4. The Purview stack for Cowork supports Audit, DSPM for AI, sensitivity labels + inheritance, IRM, Communication Compliance, and eDiscovery — but NOT DLP, data classification, Data Lifecycle Management, or Compliance Manager (per Microsoft's own capability matrix).
5. Sentinel monitoring of Cowork is achievable today via the Microsoft Copilot data connector (GA March 2026) feeding the `CopilotActivity` table from the Purview Unified Audit Log, but no official Sentinel doc names "Cowork" explicitly.

## Details

### 1. Copilot Cowork architecture and identity model
Microsoft 365 Copilot Cowork is an agentic system that plans and executes long-running, multi-step tasks across Microsoft 365 — sending email through Outlook, posting in Teams, creating/editing Word/Excel/PowerPoint/PDF files, managing calendar, reorganizing OneDrive/SharePoint folders, running enterprise search and deep research, and running scheduled/event-driven prompts. Crucially, **it runs entirely in a sandboxed Microsoft cloud environment under the signed-in user's delegated Microsoft Graph permissions** — "it operates with the users' Microsoft permissions and can use Microsoft Graph to read and operate on data in one's Microsoft tenant" (PromptArmor). This is architecturally different from Anthropic's Claude Cowork, which runs locally on the user's desktop.

**Models:** At GA, Cowork runs on Anthropic Opus 4.8 and Sonnet 4.6, with Anthropic operating as a Microsoft subprocessor (prompts and grounding content leave first-party Microsoft infrastructure to reach Anthropic for inference). GPT 5.5 is available via Frontier; a cost-optimized Microsoft "Cowork 1" model was announced as coming soon. Admins can turn the Anthropic model family on/off tenant-wide or scope it to specific users/groups under Copilot > Settings > AI providers operating as Microsoft subprocessors.

**Licensing:** Cowork requires a Microsoft 365 Copilot license — the enterprise add-on is **$30 per user/month on annual commitment (held steady since launch), per Microsoft official pricing verified July 16, 2026 — note the SMB Copilot Business SKU was permanently cut from $30 to $21/user/month on Dec 1, 2025 for organizations under 300 users** (relevant, since a 5-person team likely sits in a sub-300-seat tenant on the Business SKU) — plus usage-based billing configured. Users need an Exchange Online mailbox (prompts/responses are stored in the user's mailbox, which is also what makes eDiscovery work). Cowork is excluded from GCC/government tenants (FedRAMP not yet supported).

**Frontier history and GA transition:** Cowork launched ~March 30, 2026 in the Frontier preview program (free/unmetered). It reached GA June 16, 2026 at 8:00 AM PST worldwide. Tenants with Frontier Cowork usage between March 30 and June 16 received a grace period with no billing until July 1, 2026; all other tenants were billed from GA. **By July 1, 2026, usage-based billing must be configured or Cowork access is suspended.**

**Copilot Credits billing:** Cowork is metered in Copilot Credits ($0.01/credit under pay-as-you-go; P3 pre-purchase commitments earn a discount). Task cost is a function of four inputs: model use, context retrieval, tool calls, and runtime. This sits *on top of* the per-user Copilot license — the license is the entry point; credits meter actual agent work. Admins manage this via the M365 admin center Cost Management dashboard (spending limits/hard caps at tenant/group/user level, budgets, alerts, credit-request workflows). Users can type `/cost` in a task to see credits consumed.

**Admin management model change at GA:** In the Frontier preview, Cowork was managed via **All Agents > Cowork** with agent-based access control. At GA, per Microsoft Learn: "Copilot Cowork is now generally available and is no longer managed in the Microsoft 365 admin center by selecting All Agents > Cowork... The agent-based access control that was available in the Preview version isn't used to manage user access. Cowork is now an agentic system (different from an agent)." It is now accessed via **Agents > All Agents**, selecting Cowork from the dropdown. **User access is now controlled by enabling usage-based billing** plus a discoverability setting; if an admin makes Cowork discoverable but doesn't enable billing, users can request access in-app. Availability can still be set to All users / Specific users or groups / Blocked, and admins can deploy and pin Cowork. Note: country/region scoping is not supported — use security groups.

### 2. Core risk model
**Indirect prompt injection (the #1 risk; OWASP LLM01).** An attacker plants instructions in content Cowork reads, hijacking the agent to act under the user's identity. PromptArmor's threat model enumerates the injection/execution vectors: custom skills (auto-loaded from OneDrive), emails (inbox triage), Teams messages, SharePoint/OneDrive files (including hidden text, speaker notes, comments, metadata), plugin/connector responses, web search & deep research, the code-interpreter/command-execution sandbox, Adaptive Cards, and calendar invites/meeting subjects.

**Documented real-world incident.** On May 13, 2026, PromptArmor published "Microsoft Copilot Cowork Exfiltrates Files," demonstrating that a poisoned SKILL.md file (five malicious lines inside an 81-line skill) could cause Cowork to exfiltrate M365 files and PII. The mechanism: unlike other sensitive actions, **sending emails and Teams messages *to the active user* did not require human approval**; the injection told Cowork to post a Teams message to the user containing pre-authenticated file download links embedded as query parameters to an attacker-controlled site via malicious HTML image tags, so opening the message unfurled/leaked the links. It achieved a high success rate against state-of-the-art models including Claude Opus 4.7. As of the May 2026 disclosure, PromptArmor reported the send-to-self approval behavior was still by design. This hit the top of Hacker News. Microsoft's public guidance states Cowork asks permission before sensitive actions — a direct tension flagged by trade press (WinBuzzer, May 26, 2026).

**Related/comparable disclosures.** **EchoLeak (CVE-2025-32711, CVSS 9.3), a zero-click prompt injection against M365 Copilot, was disclosed by Aim Security (Aim Labs) researchers Pavan Reddy and Aditya Sanjay Gujral in June 2025; MSRC classified it critical (CVSS 9.3) as "AI command injection in M365 Copilot," introducing the "LLM Scope Violation" class, patched server-side June 2025 with no known in-the-wild exploitation.** The August 2024 Slack AI exfiltration (PromptArmor) illustrates the same class. PromptArmor also reported "Skill Accesses Deepseek Despite Copilot Cowork Admin Opt-out." Independent skill-supply-chain research confirms the systemic skill risk: **Snyk's ToxicSkills audit (Feb 5, 2026) scanned 3,984 skills from ClawHub/skills.sh and found "13.4% of all skills, or 534 in total, all contain at least one critical-level security issue," with 36.82% (1,467) containing at least one flaw and 76 containing confirmed malicious payloads**; Trail of Bits and HKUST (SkillCloak evading scanners >90% of the time) corroborate.

**Oversharing via Microsoft Graph.** Cowork inherits every share the signed-in user has — stale Teams memberships, org-wide SharePoint sites, "anyone-with-the-link" OneDrive shares. Existing oversharing becomes the agent's effective attack surface. This is why input-side SharePoint governance (Section 3) is foundational.

### 3. SharePoint access governance tools
All of the following are SharePoint Advanced Management (SAM) features, provided at no extra cost to tenants with Microsoft 365 Copilot licenses since December 2024. Prerequisites: a SharePoint Premium – SharePoint Advanced Management subscription (included with Copilot), the latest SharePoint Online Management Shell, and connection as SharePoint Administrator.

- **Restricted Access Control (RAC):** Restricts *all* access to a site to a specified Entra security group; content is then visible in Copilot/Cowork only for that group. Setup: SharePoint admin center → Policies → Access control → Site-level access control (enable), then Sites → Active sites → select site → Settings → Restricted site access → add security groups → Save.
- **Restricted Content Discovery (RCD):** Microsoft's recommended long-term control to exclude a site from tenant-wide search and Copilot/agentic grounding *without changing permissions* — users can still find files they own or recently used. Set per site: Active sites → site → Settings → toggle "Restrict content from Microsoft 365 Copilot", or via PowerShell (`Set-SPOSite`/`Set-PnPTenantSite -RestrictContentOrgWideSearch $true`). Cannot be applied to OneDrive sites. Microsoft cautions that overuse degrades search/Copilot quality and adds search-index latency. Site admins can now control RCD once the tenant is enabled for "delegated content discoverability" via PowerShell.
- **Block Download policy:** Copilot can still ground on content but cannot return a downloadable link (mitigating the PromptArmor exfil pattern). `Set-SPOSite -Identity <SiteURL> -BlockDownloadPolicy $true`, or by label: `Set-Label -Identity <label> -AdvancedSettings @{BlockDownloadPolicy="true"}`. Site-level only, not tenant-wide.
- **Site Access Reviews:** SharePoint admin center → Reports → Data access governance → open a report → select up to 100 sites → Initiate site access review. Delegate to site owners; run before Cowork rollout and on a recurring cadence.

*Limitation to verify with client tenant:* RAC/RCD interaction with nested groups has historically been a concern; confirm group-nesting support against current Microsoft documentation before relying on it (my research did not surface a definitive current Microsoft statement on nesting).

### 4. Microsoft Purview governance stack for Cowork
Microsoft documents Cowork's Purview support *separately* from mainline M365 Copilot because "Cowork introduces long-running, multi-step work across apps [that] can result in different behaviors and feature support." The official capability matrix (Microsoft Learn, "Use Microsoft Purview to manage data security & compliance for Microsoft 365 Copilot Cowork," updated 2026-06-17):

| Capability | Supported for Cowork |
|---|---|
| DSPM and DSPM for AI (classic) | ✓ |
| Auditing | ✓ |
| Data classification | ✕ |
| Sensitivity labels | ✓ |
| Encryption without sensitivity labels | ✓ |
| **Data loss prevention** | **✕** |
| Insider Risk Management | ✓ |
| Communication compliance | ✓ |
| eDiscovery | ✓ |
| Data Lifecycle Management | ✕ |
| Compliance Manager | ✕ |

- **Purview Audit:** Cowork prompts/responses are captured in the unified audit log. Typical Cowork events: a user starts a new Cowork conversation; adds/removes/shares a skill or plugin; runs a scheduled prompt; starts a browser task; uploads a file to Cowork; Cowork creates an artifact in OneDrive on behalf of a user. Log entries include agent name, agent ID, and version. Searchable via the Audit solution and via Activity Explorer (AI activities tab). Audit Standard provides these at no extra cost.
- **DSPM for AI:** One-click policies available for Cowork: "Protect your data with sensitivity labels," "DSPM for AI – Detect risky AI usage," and "DSPM for AI – Unethical behavior in AI apps." Data risk assessments include the default weekly "Protect your data from potential oversharing risks" assessment and a custom "Protect sensitive data references in Copilot and agent responses" assessment. **Cowork-specific limitation (per Microsoft):** although Cowork interactions display in Activity Explorer's AI activities tab, "they don't display in the Apps and agents dashboard or the AI observability page."
- **Insider Risk Management:** In scope at GA. Use the **Risky AI usage** policy template to detect prompt injection attempts and access to protected materials; signals integrate into Microsoft Defender XDR.
- **Adaptive Protection:** Ties IRM risk scoring to automatic enforcement — DLP, Data Lifecycle Management, and Conditional Access policies dynamically apply block / block-with-override / warning based on a user's insider-risk level (minor/moderate/elevated/high). Microsoft's guidance for Copilot explicitly recommends Adaptive Protection to "block high risk users from accessing sensitive content using Copilot and agents." Requires E5-level licensing (IRM + Conditional Access). Note: because native DLP isn't wired to Cowork yet, the DLP arm of Adaptive Protection won't inspect Cowork-drafted content directly — the Conditional Access and access-blocking arms still apply.
- **Communication Compliance:** Supported for Cowork; detects regulatory/business-conduct violations in prompts and responses (see "Configure a communication compliance policy to detect for generative AI interactions").
- **Sensitivity labels & auto-labeling:** Supported. Cowork displays the highest-priority (most restrictive) label among referenced items in responses/citations. For encrypted content, users need VIEW and EXTRACT usage rights. **Label inheritance:** when Cowork creates new Word/PowerPoint/Outlook content from labeled source(s), the source label (and its protection/markings) is automatically inherited; with multiple sources, the highest-priority label wins. Users can override unless mandatory labeling is set. Recommendation: enable sensitivity labels for SharePoint/OneDrive and configure auto-labeling policies (Purview portal → Information protection → Auto-labeling policies) so labels apply without relying on manual user action.
- **DLP — current state (critical for banking):** **Native DLP support for Cowork has NOT shipped as of the research date.** Microsoft's Cowork Purview matrix marks Data Loss Prevention "✕", and Microsoft's June 2026 messaging notes DLP support is "coming later." (Note a documentation tension: the Cowork admin-governance page contains generic language that "Microsoft Purview DLP policies apply to Copilot agent interactions" — this reflects the general M365 Copilot DLP location, not confirmed Cowork enforcement; the authoritative Cowork-specific matrix says DLP is unsupported. Flag this ambiguity and treat DLP as unavailable for Cowork until the matrix flips.)
  - **Interim compensating controls Microsoft/industry recommend:** (1) **Exchange Online transport-layer DLP / mail-flow inspection** — because it inspects mail at the SMTP transport layer, it catches sensitive data leaving via email *regardless of whether a human or Cowork drafted it*; this is the key substitute for outbound-mail leakage. (Caveat: legacy Exchange Transport Rule DLP predicates were retired in 2023 — implement this through Microsoft Purview Unified DLP's Exchange location, not deprecated ETR conditions.) (2) SharePoint RAC/RCD/Block Download to reduce what Cowork can reach and exfiltrate. (3) Sensitivity labels with encryption (enforced via EXTRACT usage right) — protection travels with the file even though DLP doesn't yet see Cowork. (4) IRM + Adaptive Protection to constrain high-risk users. (5) A newer Purview control (public preview June, GA July 2026) lets DLP restrict *external* emails from being referenced/grounded in Copilot — useful to keep unvetted external content out of Cowork context.

### 5. Web browsing / research security controls
Cowork's browser use runs in a **hidden tab in the user's local Microsoft Edge**, using the user's existing SSO/cookies/sessions — "the agent has exactly the same access to sites that you have when you browse by hand." Credentials/cookies/session tokens stay on the device and are not sent to Cowork's servers. Existing Entra sign-in, Conditional Access, and Purview policies apply unchanged.

- **Enable/disable:** Off by default. Tenant admins enable it at Copilot > Settings > View All > Cowork settings → "Allow browser access" → check "Allow Cowork to use the Microsoft Edge browser to perform tasks on behalf of users." Users then see a confirmation screen (noting the feature is in preview and may make mistakes) before the first browser task.
- **Allow-list / block-list:** Cowork respects the organization's existing Edge web-browsing allowlist/blocklist and view-only policies. The relevant Edge management policies are `BrowsingWithCopilotAllowList` and `BrowsingWithCopilotBlockList`: if no domains are in the allow list, browsing is effectively disabled; blocklist entries take precedence over allowlist; supports scheme/subdomain/port scoping; HTTP/HTTPS only. Microsoft Edge for Business surfaced admin allow/block-list management for Copilot browsing (promoted ~July 6, 2026). Browser tasks inherit the same Conditional Access, DLP, and tenant browsing policies already applied to users.
- **Built-in defenses / caveats:** The confirmation screen and per-action approval gate are the main built-in controls. This is a preview feature; because it reuses the live authenticated Edge session, it is a genuine injection/exfil surface — for a bank, keep the browsing allow-list tight (only vetted business web apps) or leave browser access off during the initial pilot. ("Researcher with Computer Use"/sandboxed browsing is an Anthropic Claude Cowork concept; Microsoft's Cowork browser use is the local-Edge model described above — do not conflate the two.)

### 6. Custom skills and plugin governance
- **Custom skills (SKILL.md):** Cowork auto-discovers user-authored skills from a specific OneDrive path (`/Documents/Cowork/skills/`, folder `skills` lowercase, file `SKILL.md`) at the start of each session — with no admin review, prompt, or warning. **Microsoft explicitly states: "Custom skills created by users aren't validated by Microsoft. Review custom skill outputs carefully."** Anyone with OneDrive write access (including via a compromised synced endpoint) can plant persistent agent instructions. Users can create up to 50 custom skills. **Recommended control:** require organization-level admin review/approval before custom skills are enabled for high-risk users (executives, finance, legal — and, for a bank, marketing handling MNPI/customer data); audit the OneDrive skills folder and delete unrecognized skills. **Also prohibit "Don't ask again"** on Cowork write actions (send email, post to Teams, schedule meeting, modify/delete files) so the per-action approval gate stays active every invocation.
- **Plugins:** At GA, partner plugins available include Enosix, Harvey, LSEG, Miro, monday.com, Moody's, Morningstar, S&P Global Energy, and TeamsMaestro (Databricks via sideloading); Microsoft Fabric (Fabric IQ/Power BI) and Dynamics 365 (Sales, Customer Service, ERP) are live. Coming soon: Adobe, Atlassian, Box, Canva, CB Insights, MoneyForward, Templafy. Plugins from the M365 App Store go through Microsoft validation but still expand Cowork's action surface. **Read vs. read & write matters:** a "read & write" plugin can create/update records in the external service. **Recommended control:** block partner plugins that take write actions in external services (Copilot > Agents > Tools > <Plugin> > Block/Unblock); for a security-oriented posture, block all plugins initially. Admins can deploy plugins org-wide (users can't remove, only toggle off per session) or restrict the catalog. First use of a partner plugin prompts the user to authenticate/authorize the connection.

### 7. Identity and Conditional Access hardening (for 5 real users)
- **Phishing-resistant MFA:** MFA is measured to reduce identity-compromise risk by **99.22%, per Microsoft's peer-reviewed Azure AD measurement study (cited on Microsoft Learn): MFA "reduced the risk of compromise by 99.22% across the population, and by 98.56% even when the password had already leaked"; Microsoft now restates this as blocking "more than 99.2% of account-compromise attacks."** Require FIDO2 security keys, passkeys (Entra now supports synced passkeys), Windows Hello for Business, or certificate-based auth. For a 5-person team this is entirely practical — issue two FIDO2 keys per user (primary + backup) and set a Conditional Access "phishing-resistant MFA" authentication-strength requirement.
- **Conditional Access:** Require phishing-resistant MFA for Microsoft 365 (and Cowork) access; require compliant/Intune-managed devices; use session controls (browser-only, no download) for unmanaged endpoints touching labeled sites. Build every policy in report-only first, keep a break-glass account excluded, then enforce. Continuous Access Evaluation (CAE) and Token Protection shorten the window a stolen token is useful.
- **Entra ID Protection (P2):** Use sign-in-risk and user-risk detections to drive automatic controls — most orgs set "high user risk or high sign-in risk blocks access," with step-up at medium risk. Make the Cowork-blocking risk threshold explicit and documented rather than default. P2 is also required for the risk-based Conditional Access and the IRM/Adaptive Protection integration.
- **Real (non-service) identity model:** Cowork acts as the user, not a service principal, so all controls above attach cleanly to the five human identities. Apply least privilege to each account (this directly shrinks Cowork's Graph reach) and enforce the same hardening on any admin accounts managing Cowork/billing.

### 8. Monitoring and incident response
- **Microsoft Sentinel — verified status:** The **Microsoft Copilot data connector for Microsoft Sentinel** entered public preview in early February 2026 and reached **GA in March 2026** (per the Microsoft Tech Community Sentinel blog update note: "*Please note that this connector is now in GA status as of March, 2026*"). It ingests Copilot activity records already emitted to the Purview Unified Audit Log into a Sentinel table named **`CopilotActivity`**, powering analytics rules, custom detections, workbooks, hunting, and automation. Record types include CopilotInteraction, Create/Update/Delete CopilotPlugin, CreateCopilotWorkspace, CopilotPromptBook operations, CopilotForSecurityTrigger, and CopilotAgentManagement. **Setup:** install from the Sentinel Content Hub (search "Microsoft 365 Copilot"), enable as Global Admin or Security Admin; it's a single-tenant connector and ingests only where Copilot licenses/SCUs are active; ingestion costs apply. A separate **Agent Identities Asset Connector for Microsoft Sentinel** entered public preview (announced June 16, 2026) and adds agent identity/ownership/permission context, correlating with the Agent 365 Observability and Copilot connectors for identity-aware investigations and end-to-end traceability.
  - **Important sourcing caveat:** Cowork activity (including each browser task) *is* officially documented as written to the unified audit log (Microsoft Learn, "Manage Copilot Cowork for your organization"). However, **no official Sentinel documentation names "Cowork" explicitly** as a monitored source — Cowork's Sentinel visibility is achieved via the general Copilot connector → Purview UAL → `CopilotActivity` path, which is an inference from two officially-documented facts rather than a single Microsoft statement about Cowork-in-Sentinel. (Note a minor documentation nuance: the Azure Monitor query-reference page shows example KQL against an `LLMActivity`/`RecordType` alias while the ingest table is documented as `CopilotActivity`.) The prior research's observation that this topic is better covered in trade press than official docs is confirmed.
- **eDiscovery scope for Cowork:** In scope — conversation transcripts (full prompts/responses), files Cowork created (docs/decks/PDFs/images saved to OneDrive), scheduled prompts (prompt text and each run's conversation), and uploaded files retained in OneDrive/conversation. Because prompts/responses live in the user's mailbox, create a case and search the user's mailbox with the query-builder condition Type → Contains any of → "Copilot activity" (covers all Copilot/AI activity), then export or add to a review set.
- **Incident response guidance:** My research did not surface a dedicated Microsoft-published incident-response playbook specific to Copilot Cowork misuse. Microsoft's general Copilot Control System security/governance guidance and the IRM "Risky AI usage" template + Adaptive Protection are the closest official IR-relevant controls. For the client, build a Cowork-specific IR runbook (revoke session via CAE, disable Cowork availability for the group, audit the user's OneDrive skills folder, hunt `CopilotActivity` in Sentinel, check for anomalous self-directed Teams/Outlook messages) rather than relying on an off-the-shelf Microsoft playbook.

### 9. Regulatory/compliance considerations for financial services
- **Data residency:** Cowork stores conversation content in the tenant's local region geography by default and supports Advanced Data Residency (ADR) and Multi-Geo. The Anthropic subprocessor inference path means prompts/grounding content leave first-party Microsoft infrastructure (and, per PromptArmor's NIST AI RMF mapping, may involve Anthropic processing outside the EU Data Boundary — update DPIA/ROPA accordingly). Cowork is not available in GCC/government tenants (no FedRAMP yet).
- **FFIEC/GLBA relevance:** No Microsoft whitepaper specific to Cowork-in-banking surfaced in this research. Third-party MSPs specializing in financial institutions (e.g., ABT/myabt.com) map M365 Copilot/Cowork governance to FFIEC examination areas (access controls, third-party risk, DLP) and GLBA/FTC Safeguards Rule technical-safeguards requirements, and to NIST AI RMF. Key examiner-readiness points: GLBA requires technical safeguards for customer NPI; FFIEC explicitly recognizes DLP as a compliance tool (a gap for Cowork given DLP isn't supported yet — document this as a known limitation with compensating controls); audit-trail requirements apply to anything Cowork drafts that reaches a customer or regulator (Purview Audit + eDiscovery provide the trail; document what Cowork generated and what a human approved). PromptArmor's guide provides a ready NIST AI RMF (GOVERN/MAP/MEASURE/MANAGE) control-narrative mapping usable as an audit-evidence package.
- **Marketing-department specifics:** A bank marketing team may touch customer lists, campaign data, and occasionally material non-public information. Treat any site holding NPI/MNPI with RAC + Block Download + a sensitivity label carrying encryption, and keep those sites out of Cowork grounding via RCD until permissions are reviewed.

### 10. Comparative context: Microsoft Copilot Cowork vs. Anthropic Claude Cowork
Same name, shared Claude models, different products. **Claude Cowork is a local desktop agent** on the user's machine with access to local files, browser sessions (authenticated with the user's cookies), shell execution, and MCP connections; **Microsoft Copilot Cowork is a cloud-tenant agent** that works only with tenant data reachable via Microsoft Graph. Both are vulnerable to the same indirect-prompt-injection class — PromptArmor demonstrated file exfiltration against both. Security-research notes on Claude Cowork worth carrying into the client conversation: within 48 hours of Claude Cowork's January 2026 launch, PromptArmor demonstrated a Word-document white-text injection exfiltrating financial docs/partial SSNs; and multiple vendors (TrueFoundry, MintMCP, Pluto Security, Backslash, Palo Alto Networks) report that Claude Cowork activity is excluded from Anthropic's audit logs, Compliance API, and data exports on all tiers — Anthropic advises against regulated workloads. **This is a key differentiator in Microsoft's favor for a bank:** Microsoft Copilot Cowork inherits the M365 compliance boundary (Audit, eDiscovery, IRM, Communication Compliance, sensitivity labels) even though DLP is still pending, whereas Claude Cowork's native governance blind spot is more severe. If the client evaluates Claude's Microsoft 365 connector as an alternative, note Microsoft's own testing claimed Copilot Cowork ran materially cheaper than Claude Cowork via the M365 connector, and Claude Cowork requires Team/Enterprise tier for meaningful admin governance.

## Recommendations
**Stage 0 — Before enabling Cowork (do this week):**
1. Keep Cowork **Blocked** or scoped to no users until controls below are in place; confirm usage-based billing is deliberately configured (nothing runs until an admin enables it), with hard spending caps at group/user level.
2. Run SharePoint Data Access Governance reports + Site Access Reviews on all sites the 5 marketing users can reach; remediate "Anyone/Everyone/org-wide" sharing.

**Stage 1 — Identity and data foundation:**
3. Enforce phishing-resistant MFA (FIDO2/passkeys) and risk-based Conditional Access (block high user/sign-in risk; compliant device required) for the marketing group; keep a break-glass admin. Requires Entra ID P2.
4. Apply RAC to sensitive sites, RCD to sites that shouldn't ground Copilot, and Block Download on sites holding NPI/MNPI; enable sensitivity labels for SharePoint/OneDrive and turn on auto-labeling.

**Stage 2 — AI-specific governance:**
5. Scope Cowork to a dedicated Entra security group (the 5 users) via Agents > All Agents; scope the Anthropic subprocessor to that same group.
6. Require admin review/approval of custom SKILL.md files; audit the OneDrive skills folder; set policy prohibiting "Don't ask again" on write actions.
7. Block all external plugins initially; allow only vetted read-only plugins as business need is proven; block any read & write plugin absent a documented case.
8. Leave Cowork browser access **off** for the initial pilot; if enabled later, restrict `BrowsingWithCopilotAllowList` to specific vetted business web apps.

**Stage 3 — Monitoring, compliance, and DLP substitute:**
9. Implement Microsoft Purview **Unified DLP on the Exchange (transport) location** as the interim substitute for absent Cowork DLP — it inspects outbound mail regardless of human vs. AI authorship. Add the new control that blocks external emails from Copilot grounding.
10. Turn on IRM "Risky AI usage" + Adaptive Protection (block-with-override for elevated-risk users). Install the Sentinel Copilot data connector (and Agent Identities connector) and build hunts on `CopilotActivity`, especially self-directed Teams/Outlook messages and skill/plugin lifecycle events.
11. Author a Cowork-specific IR runbook and a client-facing acceptable-use policy (no pasting customer NPI into prompts; approve every write action; report unexpected agent messages).

**Benchmarks that change the plan:**
- **When native Purview DLP for Cowork ships** (matrix flips DLP to ✓): fold Cowork into existing Copilot DLP policies and re-evaluate the Exchange-transport substitute as defense-in-depth rather than the primary control.
- **When Microsoft publishes GCC/FedRAMP support**, revisit whether a stricter tenant model is warranted.
- **If credit consumption or incident volume rises**, tighten spending caps and re-scope the pilot group.
- **If the send-to-self approval gap is patched**, the "no Don't ask again" policy can be relaxed — but keep it until Microsoft confirms the fix.

## Caveats
